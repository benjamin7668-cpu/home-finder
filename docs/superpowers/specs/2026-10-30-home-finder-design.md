# 우리 집 어디로? — 부부 직장 기반 내 집 마련 입지 추천 (설계)

- 작성일: 2026-10-30
- 용도: 실습·포트폴리오용 데모 (로컬 실행, 배포 없음)
- 상태: 설계 승인 완료 → 구현 계획 작성 전

## 1. 목표
부부의 직장 주소 두 곳과 매매 예산을 입력하면, 수도권 아파트 실거래가를 바탕으로
"둘 다 통근이 무난하고, 생활 인프라가 좋고, 예산 안에 드는" 법정동을 순위로 추천하고
동네별 가격 흐름을 보여 준다.

### 사용자가 정한 것
- 기준: 부부 대중교통 통근 시간 + 예산 + 생활 인프라, 가격 흐름은 표시
- 통근 수단: 대중교통 (지하철·버스·도보)
- 대상 지역: 수도권 전체 (서울·인천·경기 83개 시·군·구, 2026-07 인천 개편 반영: 제물포구·영종구·서해구·검단구)
- 실제 API 사용 (ODsay·카카오 키 신규 발급), 캐시 사용
- 구현 방식: Python FastAPI + 정적 웹페이지 + SQLite 캐시

### 가정 (변경 가능)
- 매매, 아파트만 대상
- 추천 단위는 법정동 (단지 단위 아님)
- 출근 시간대 입력은 제외 (ODsay 기본 길찾기에 출발 시각 옵션이 없는 것으로 파악, 구현 시 재확인)

### 범위 밖
전세·빌라·오피스텔, 단지 단위 추천, 회원/저장 기능, 학군 점수, 대출 계산, 배포

## 2. 외부 데이터와 키

| 용도 | 출처 | 환경변수 | 발급 |
|---|---|---|---|
| 아파트 매매 실거래가 | 국토교통부 `RTMSDataSvcAptTrade` (data.go.kr) | `DATA_GO_KR_API_KEY` | 보유 (`mcp-servers/real-estate-mcp/.env`와 동일 키) |
| 대중교통 통근 시간 | ODsay LIVE `searchPubTransPathT` | `ODSAY_API_KEY` | https://lab.odsay.com 가입 → 서버용 키 발급, 호출 IP 등록 |
| 주소→좌표, 주변 시설 | 카카오 로컬 API | `KAKAO_REST_API_KEY` | https://developers.kakao.com 앱 생성 → REST API 키 |
| 지도 표시 | 카카오맵 JavaScript SDK | `KAKAO_JS_KEY` | 같은 앱의 JavaScript 키, 플랫폼 → Web 도메인에 `http://localhost:8000` 등록 |

`KAKAO_JS_KEY`만 브라우저에 노출되며(도메인 제한으로 보호), 나머지 키는 서버에만 둔다.

## 3. 구조

```
home-finder/
├── .env / .env.example
├── pyproject.toml            # uv: fastapi, uvicorn, httpx, python-dotenv, pytest
├── app/
│   ├── main.py               # FastAPI: 정적 파일, /api/recommend(SSE 진행상황), /api/geocode
│   ├── config.py             # 키 로드·누락 확인
│   ├── regions.py            # 수도권 시·군·구 코드·이름 목록
│   ├── cache.py              # SQLite key/value + TTL
│   ├── warmup.py             # 실거래가·동네 좌표 미리 받기
│   ├── sources/
│   │   ├── molit.py          # 실거래가 조회·파싱
│   │   ├── odsay.py          # 대중교통 최단 시간·노선 요약
│   │   └── kakao.py          # 지오코딩, 카테고리/키워드 개수
│   ├── recommend.py          # 후보 좁히기·점수 (외부 호출 없는 순수 함수)
│   └── static/ index.html, app.js, style.css
├── data/cache.sqlite         # 자동 생성
└── tests/
```

- `sources/*`: API 하나씩 담당, 캐시는 내부에서 처리, 정리된 dataclass 반환.
- `recommend.py`: 데이터만 받아 계산 → 가짜 데이터로 단위 테스트.
- `main.py`: 입력 → sources로 수집 → recommend로 점수 → JSON.
- 실행: `uv run uvicorn app.main:app` → http://localhost:8000

## 4. 데이터 흐름

입력: 예산(억 원), 면적 구간(59형 50~65㎡ / 84형 76~90㎡ / 전체), 직장 A·B 주소, 각자 최대 통근 시간(기본 60분).

| 단계 | 내용 | 외부 호출(캐시 없을 때) |
|---|---|---|
| ① 수집 | 83개 시·군·구 × 최근 12개월 실거래가, 해제 거래(`cdealType`) 제외 | 약 996회 (동시 10개, 1~2분) |
| ② 예산 필터 | 법정동별·면적 구간별 최근 6개월 중위가 ≤ 예산, 거래 3건 미만 제외 | 0 |
| ③ 지오코딩 | 동네("시군구 동명")·직장 주소 → 좌표 | 동당 1회, 영구 캐시 |
| ④ 거리 필터 | 직선거리 합 상위 10곳 (ODsay 무료 한도 하루 30회) | 0 |
| ⑤ 통근 | 10곳 × 2명 ODsay 최단 시간, 최대 통근 초과 시 제외 | 최대 20회 |
| ⑥ 인프라 | 통근 통과 곳(최대 10곳), 반경 1km 지하철역(SW8)·학교(SC4)·대형마트(MT1)·병원(HP8)·공원(키워드) 개수 | 최대 50회 (카카오) |
| ⑦ 점수·순위 | 상위 10곳 반환 | 0 |

## 5. 점수 (후보 간 0~100 정규화)
- 통근: `합계 + 0.5 × |A−B|` 작을수록 높음 (공평성 반영)
- 인프라: 지하철역 3, 학교 2, 대형마트 2, 병원 1, 공원 1 가중합, 항목별 상한
- 예산 여유: `(예산 − 중위가) / 예산` 클수록 높음
- 종합: 통근 0.5 + 인프라 0.3 + 예산 0.2 (슬라이더로 조절, 재계산은 브라우저에서)

가격 흐름(점수 미반영): 12개월 월별 중위가·거래 건수, 변화율 = 12개월 구간의 처음 3개월 중위 vs 최근 3개월 중위 (약 9개월 간격).

결과 예시:
```json
{ "name": "성남시 분당구 정자동", "median_price": 9.8, "deals_6m": 42,
  "commute": {"a": {"min": 38, "transfers": 1, "summary": "2호선 → 신분당선"}, "b": {...}},
  "infra": {"subway": 2, "school": 5, "mart": 1, "hospital": 12, "park": 3},
  "trend": [{"ym": "2025-11", "median": 9.4, "count": 7}], "trend_change_pct": 4.3,
  "scores": {"commute": 82, "infra": 71, "budget": 40, "total": 72} }
```

## 6. 화면
- 한 페이지: 왼쪽 입력·비중 슬라이더·결과 목록, 오른쪽 카카오 지도 (좁은 화면에서는 세로 배치)
- 지도: 직장 마커 2개, 추천 동네 번호 마커(점수별 색), 선택 시 반경 1km 원
- 상세 패널: 가격 흐름 SVG 차트(꺾은선 + 거래 건수 막대, 거래 없는 달은 끊김), A/B 통근 시간·환승·노선, 인프라 개수, 점수 구성 막대, 출처·기준일
- 진행 상황 표시(SSE): "실거래가 수집 중 (34/83)"
- 흰 바탕 + 포인트 색 1개, 다크 모드 지원

## 7. 오류 처리 (수치를 지어내지 않는다)
| 상황 | 처리 |
|---|---|
| 키 누락/오류 | 시작 시 확인, 화면 상단에 어떤 기능이 불가한지 표시 |
| 국토부 오류 | 2회 재시도, 실패 지역 제외 후 "N개 시·군·구 누락" 표시 |
| ODsay 한도 초과 | 캐시 값만 사용, 없는 후보는 "통근 확인 불가"로 순위 제외 (직선거리 추정치로 대체하지 않음) |
| 직장 주소 지오코딩 실패/모호 | 후보 최대 5개 제시 후 선택 |
| ODsay 경로 없음 | 700m 이내면 도보 시간, 그 외 제외 |
| 예산 내 동네 없음 | 안내 + 가장 가까운 가격대 3곳 참고 표시 |
| 거래 3건 미만 | 제외, "거래가 적어 제외된 동네 N곳" 표시 |

## 8. 캐시
SQLite 단일 테이블 `cache(key TEXT PRIMARY KEY, value TEXT, fetched_at REAL, ttl REAL NULL)`.

| 데이터 | 키 예시 | TTL |
|---|---|---|
| 두 달 전 이전 실거래가 (신고 기한 지나 확정) | `molit:41135:202608` | 영구 |
| 이번 달·지난달 실거래가 | `molit:41135:202610` | 1일 |
| 통근 | `odsay:37.512,127.059>37.401,127.108` (소수 셋째 자리) | 30일 |
| 인프라 | `kakao:infra:<동코드>` | 30일 |
| 지오코딩 | `kakao:geo:<문자열>` | 영구 |

## 9. 테스트
- 단위(pytest, 외부 호출 없음): recommend(예산·거래수·통근 필터, 정규화, 공평성, 비중 변경 시 순위 변화), molit 파싱(저장한 XML 샘플: 금액 "98,000"→9.8억, 해제 거래 제외, 면적 구간), cache(TTL 만료, 영구 보관)
- 실제 API(선택): `pytest -m live`로 세 API 각 1회 응답 형식 확인
- 최종 확인: 서버 실행 후 Playwright로 예시 입력(A 강남역, B 상암DMC, 8억, 59㎡) → 목록·마커·상세 차트 스크린샷 확인

## 10. GitHub 업로드 (구현 완료 후)
- 목적: 사용자가 집에서도 코드를 받아 실행할 수 있게 사용자 GitHub 계정에 저장소로 올린다.
- `home-finder/`를 git 저장소로 만들고, `.gitignore`에 `.env`, `data/cache.sqlite`, `.venv/`, `__pycache__/`를 넣어 **키와 캐시는 올리지 않는다**. 대신 `.env.example`과 README(키 발급·실행 방법)를 올린다.
- 업로드 직전 커밋 내용에 키 문자열이 없는지 검사한다.
- 저장소 이름·공개 여부는 업로드 시점에 사용자에게 확인한다.
- 다른 컴퓨터에서는 `git clone` → `.env` 작성 → `uv run uvicorn app.main:app`으로 실행한다. (GitHub는 코드 보관용이며, 웹에서 바로 열리는 배포는 범위 밖)
